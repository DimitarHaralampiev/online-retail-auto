# Online Retail Auto

Начална основа на онлайн магазин за автоаксесоари и части за България със собствен склад.

## Локално стартиране

Изисква Node.js 20.9+ и npm.

```bash
npm ci
npm run dev
```

Отвори http://localhost:3000. Името е временно. `/catalog` съдържа примерни продукти, търсене и филтри. `/inventory-demo` показва складови операции.

## Проверки и production build

```bash
npm run typecheck
npm test
npm run build
npm start
```

`typecheck` проверява TypeScript, `test` изпълнява вградения Node.js test runner чрез tsx, `build` подготвя production версия, а `start` я стартира след успешен build. Складовите тестове проверяват резервиране, продажба, отказ от резервация, връщане и невалидни количества.

## Структура

- `src/app/page.tsx`: начална страница.
- `src/app/catalog/`: каталог и отделни продуктови страници.
- `src/app/inventory-demo/`: публична демонстрация на склада.
- `src/components/`: интерактивни компоненти за каталога и демонстрацията.
- `public/images/`: авторски AI изображения за дизайна и примерните продукти.
- `docs/visual-assets.md`: източник и точни описания за генерираните изображения.
- `src/lib/`: примерен каталог, складова логика и `*.test.ts` тестове.
- `src/app/layout.tsx`: общ layout и metadata.
- `src/app/globals.css`: стилове и адаптация за мобилни устройства.
- `AGENTS.md`: указания за принос към проекта.

## Работа с Git

`main` е основният клон. След първоначалния комит всички промени се правят в отделни клонове и се предлагат чрез pull request; не изпращаме нови комити директно в `main`.

- `feature/<име>` за функционалности, например `feature/inventory`.
- `fix/<име>` за поправки.
- `chore/<име>` за настройки и документация.

Започвай от актуален `main` и използвай кратки, описателни комити:

```bash
git switch main
git pull --ff-only
git switch -c feature/inventory
# Направи промените и изпълни проверките.
npm run typecheck
npm run build
git add <файлове>
git commit -m "Add inventory management"
git push -u origin feature/inventory
```

Отвори pull request към `main` с описание и резултатите от проверките. Прегледът и одобрението предхождат merge. За промени по интерфейса добавяй снимка, когато е възможно.

## План за развитие

1. Избор на име и визуална идентичност.
2. PostgreSQL/Supabase: продукти, доставчици, доставки и складови движения.
3. Защитена администрация за каталог и наличности.
4. Качване на фактури, AI разчитане и потвърждение преди заприхождаване.
5. Клиентски каталог, количка, резервация на наличности и поръчки.
6. Доставка, плащания, хостинг и резервни копия.
7. Сравняване на конкурентни цени и предложения за ценообразуване.

Текущата версия използва измислени продукти и количества. Складовите промени са само в паметта на отворената демо страница: губят се при презареждане и не променят каталога. Няма база, вход, приемане на поръчки или AI интеграция. За локалното стартиране не са необходими ключове или платени услуги.

## Складови правила и следваща интеграция

Свободни бройки = физическа наличност минус резервирани бройки. Доставката и връщането увеличават физическата наличност. Продажбата изписва предварително резервирани бройки; освобождаването отменя резервация. Не се допускат отрицателни количества или резервиране над свободната наличност.

При свързването с PostgreSQL операциите трябва да са атомарни транзакции със заключване на продуктовия запис, уникален идентификатор срещу дублиране и постоянен журнал на движенията. Клиентската проверка в демонстрацията сама по себе си не предпазва от едновременни поръчки. Реалният административен панел изисква вход и проверка на права на сървъра. Фактурите и личните данни ще се съхраняват защитено.
