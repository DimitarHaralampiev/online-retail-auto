# Online Retail Auto

Начална основа на онлайн магазин за автоаксесоари и части за България със собствен склад.

## Локално стартиране

Изисква Node.js 20.9+ и npm.

```bash
npm ci
npm run dev
```

Отвори http://localhost:3000. Името е временно. `/catalog` съдържа примерни продукти, търсене и филтри. `/inventory-demo` показва складови операции.

Добави наличен примерен продукт в количката. `/cart` позволява промяна на бройките и премахване. `/checkout` показва избор между Спиди и Еконт, доставка до тестов офис или адрес и наложен платеж или карта. Цените са примерни в EUR; доставка и окончателна сума още не се изчисляват. Използвай тестови данни за получателя.

## Проверки и production build

```bash
npm run typecheck
npm test
npm run build
npm start
```

`typecheck` проверява TypeScript, `test` изпълнява вградения Node.js test runner чрез tsx, `build` подготвя production версия, а `start` я стартира след успешен build. Складовите тестове проверяват резервиране, продажба, отказ от резервация, връщане и невалидни количества.

## Структура

- `src/app/page.tsx`: начална страница.
- `src/app/catalog/`: каталог и отделни продуктови страници.
- `src/app/inventory-demo/`: публична демонстрация на склада.

- `src/components/`: интерактивни компоненти за каталога и демонстрацията.
- `public/images/`: авторски AI изображения за дизайна и примерните продукти.
- `docs/visual-assets.md`: източник и точни описания за генерираните изображения.
- `docs/checkout-integrations.md`: реализираният демо процес и планът за реалните куриери, плащания и поръчки.

- `src/app/layout.tsx`: общ layout и metadata.
- `src/app/globals.css`: стилове и адаптация за мобилни устройства.
- `AGENTS.md`: указания за принос към проекта.

## Работа с Git

`main` е основният клон. След първоначалния комит всички промени се правят в отделни клонове и се предлагат чрез pull request; не изпращаме нови комити директно в `main`.

- `feature/<име>` за функционалности, например `feature/inventory`.
- `fix/<име>` за поправки.
- `chore/<име>` за настройки и документация.

Започвай от актуален `main` и използвай кратки, описателни комити:

```bash
git switch main
git pull --ff-only
git switch -c feature/inventory
# Направи промените и изпълни проверките.
npm run typecheck
npm run build
git add <файлове>
git commit -m "Add inventory management"
git push -u origin feature/inventory
```

Отвори pull request към `main` с описание и резултатите от проверките. Прегледът и одобрението предхождат merge. За промени по интерфейса добавяй снимка, когато е възможно.

## План за развитие

1. Избор на име и визуална идентичност.
2. PostgreSQL/Supabase: продукти, доставчици, доставки и складови движения.
3. Защитена администрация за каталог и наличности.
4. Качване на фактури, AI разчитане и потвърждение преди заприхождаване.
5. Клиентски каталог, количка, резервация на наличности и поръчки.
6. Доставка, плащания, хостинг и резервни копия.
7. Сравняване на конкурентни цени и предложения за ценообразуване.

Текущата версия използва измислени продукти и количества. Складовите промени са само в паметта на отворената демо страница: губят се при презареждане и не променят каталога. Профилите използват PostgreSQL; продуктите и складът още не са свързани с базата. Няма приемане на реални поръчки или AI интеграция. За локалното стартиране не са необходими ключове или платени услуги.

Количката запазва само продуктови кодове и количества в браузъра. Формата не записва данните на получателя в localStorage. Прегледът на поръчката е без запис в база, без товарителница и без плащане. Изборът „Банкова карта“ е подготовка на интерфейса; реален платежен доставчик предстои да бъде избран и свързан.

## Складови правила и следваща интеграция

Свободни бройки = физическа наличност минус резервирани бройки. Доставката и връщането увеличават физическата наличност. Продажбата изписва предварително резервирани бройки; освобождаването отменя резервация. Не се допускат отрицателни количества или резервиране над свободната наличност.

При свързването с PostgreSQL операциите трябва да са атомарни транзакции със заключване на продуктовия запис, уникален идентификатор срещу дублиране и постоянен журнал на движенията. Клиентската проверка в демонстрацията сама по себе си не предпазва от едновременни поръчки. Реалният административен панел изисква вход и проверка на права на сървъра. Фактурите и личните данни ще се съхраняват защитено.

## Промоции

`/promotions` показва продуктите с валидна примерна намалена цена. Стара цена, нова цена и процент намаление се виждат и в каталога. Количката и сървърният преглед използват една и съща намалена цена. Офертите са демонстрационни; реална история на цените, периоди на кампании и управление през администрация предстоят.


## Клиентски профили и PostgreSQL

`/account` предоставя регистрация, вход, изход и редакция на име и телефон. При регистрация се изискват име, имейл, валиден български телефон и парола от поне 12 символа. Checkout попълва контакта и запазената доставка от профила; полетата остават редактируеми. Отметката за запазване съхранява получателя и доставката за следващия път. Без вход гостът попълва всички задължителни полета.

Настрой база и миграция:

```bash
cp .env.example .env.local
# Задай локална парола и същата стойност в DATABASE_URL.
LOCAL_DB_PASSWORD=local-development-only docker compose up -d database
npm run db:migrate
npm run dev
```

При наличен PostgreSQL използвай отделна база и собствен `DATABASE_URL` в `.env.local`. Скриптът изисква Node.js 20.12+. Миграцията е повторно изпълнима. При преместване към хостинг приложи миграцията, прехвърли данните с `pg_dump`/`pg_restore` и смени URL; кодът остава същият. Примерната парола е само за локална разработка.

`db/001-accounts.sql` съдържа клиентите, сесиите и ограничението за опити за вход. Паролите използват scrypt и случайна сол. В базата се пази само SHA-256 хеш на сесийния токен; cookie е HttpOnly, SameSite=Lax и Secure в production. Изходът изтрива сесията на сървъра. API проверява произхода и валидира данните; профилът се определя от сесията, а не от изпратен клиентски идентификатор. Данни и пароли не се записват в localStorage.

Преди публичен старт предстоят потвърждение на имейл, възстановяване на парола, допълнителна защита от масови заявки, политика за личните данни и резервни копия. Нужни са HTTPS и PostgreSQL с постоянен диск; само данните за профила и предпочитаната доставка се записват, поръчките още са демо. Използвай тестови профили засега.
